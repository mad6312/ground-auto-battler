# グラウンド・オートバトラー 正式仕様書 - 03: 準備フェーズ進行・作戦・合成仕様

---

## 1. 準備フェーズの開始・ラウンド初期化処理

準備フェーズは全プレイヤーが同時にリアルタイム進行する。
各ラウンドの開始時、以下の処理が自動的かつ厳格な順序で実行される。

### 1.1. 出撃スロットの手札全回収
* 各ラウンド開始時、繰り出しUI（出撃スロット1～3）に配置されているカードは、**すべて手札UIへ自動的かつ確実に回収・再配置される**。前ラウンドの出撃カードがスロットに残留することは絶対にない。

### 1.2. ショップタブの初期選択
* 前ラウンドのタブ選択状態にかかわらず、毎ラウンド開始時は必ず **「ショップ」タブが初期選択** された状態にリセットされる。

### 1.3. 生存プレイヤーへのカード追加配布
脱落していない全生存プレイヤーの手札へ、ランダムなカードが1枚新しく追加配布される。
* **ラウンド別レアリティ解放条件（厳格に維持）**:
  * 第1ラウンド: コモンのみ
  * 第2ラウンド: アンコモン解放
  * 第3ラウンド: レア解放
  * 第4ラウンド: エピック解放
  * 第5ラウンド以降: レジェンド解放
* **解放済みレアリティ間の抽選比率**:
  * 各ラウンドで解放済みのレアリティのみを対象とし、ドキュメント `02_SHOP_MARKET.md` に記載のラウンド別出現率（R1～4 / R5以降）の比率に従って抽選される。未解放のレアリティが配布されることは絶対にない。

### 1.4. 各ラウンド開始時ポップアップ演出中の操作制限と配布の順序規約
ラウンド開始時、画面中央に以下の2行構成のポップアップ演出が表示される。

> ラウンド 〇  
> 残プレイヤー: △  
> （例：`ラウンド 2` / `残プレイヤー: 5`）

* **順序および操作制限の厳格な保証**:
  1. 「ラウンド 〇」ポップアップ演出を開始する。
  2. **ポップアップ演出中（約1.6秒間）の操作遮断**: 演出再生中は全画面のポインタイベントがブロックされ、プレイヤーからのカード操作（ドラッグ、右クリック）、ショップ購入、リロール、完了ボタン押下等の**あらゆる入力・操作を一切受け付けない**。
  3. ポップアップ演出中、**配布カードは手札UIに絶対に表示しない**。
  4. ポップアップ演出（約1.6秒）が正常に終了した後、全画面の操作制限が自動解除され、通常どおり操作可能な状態へ復帰する。
  5. 制限解除と同時に、配布カードが画面外（画面中央上部）から手札UI内の所定位置へ滑らかに飛翔するアニメーションを再生する。
  6. アニメーション終了後、カードが手札内の正しい整列位置に収まる。

### 1.5. ラウンド開始時のゴールド付与
毎ラウンドの準備フェーズ開始時、各生存プレイヤーへ以下のゴールドが付与される。
* **ラウンド1**: 付与なし
* **ラウンド2～4**: **10G**
* **ラウンド5以降**: **15G**

## 2. 画面ヘッダー（HUDクラスター）仕様

* **左上HUDクラスター（独立パネル）**:
  画面左上にすりガラス調（`glass-panel`）のHUDクラスターが配置され、以下の要素が横並びで美しく収容される。
  1. **ラウンド表示**: `ラウンド: 〇`（欧文Cinzel太字フォント）
  2. **自陣ステータス**: プレイヤー名、準備ランプ（点灯/消灯）、残りライフ（`♥♥♥♥♥`）
     * **プレイヤー名表示規約**: 長いプレイヤー名であっても末尾が「…」等で省略されることはなく、**名前全文が完全に表示**される。
     * ※所持ゴールド表示はショップUI上部フレームと完全一体化した台形タブへ移動・集約されたため、HUD内からは除外される。
  3. **次の対戦相手**: キャプション `次の対戦相手:` と対戦相手名が2段組で表示される。長いプレイヤー名であっても省略されることなく全文が表示される。
* **中央アナウンスバナーの画面中央絶対固定**:
  画面上部に表示される「全員の準備完了を待っています...」等のアナウンスメッセージは、HUDやサイドバー等の他UIのサイズや伸縮の影響を一切受けないよう、**画面上部中央（画面幅の50%位置）に絶対配置（`position: fixed`）で固定表示**される。
* **ロビー画面での完全非表示**:
  ロビー画面表示中（未エントリーおよびマッチング前）は、HUDクラスターのコンテナ枠（`#hud-dashboard-cluster`）自体が完全に非表示（`hidden`）となり、不自然な枠線や楕円が表示されることはない。

## 3. 手札UIのカード自動整列順序および画面左右端最大拡張仕様

### 3.1. 画面左右端付近までの最大幅拡張（改修後正式仕様）
* 手札UIコンテナ（`#hand-section-wrapper`）は、固定幅制限を排し、**画面の左右端付近（`width: calc(100% - 32px)`）まで最大幅を確保**して展開される。
* 画面の広大な表示領域を余すことなく活用することで、多数の手札カードを所持している場合でも余裕をもって水平に並べることが可能となる。
* カードは重なりのない水平一列（水平スクロール対応）で中央揃えに展開され、ホバー時はカードが上部へ快適に浮上・拡大（`translateY(-4px)`）して高い直感的操作性を担保する。

### 3.2. カード自動整列順序
手札UIに表示されるカードは、常に以下の優先順位に従って**すべて左から右へ自動整列**される。カードの追加・購入・移動・合成が行われるたびに、この並び順が一貫して適用される。

| 優先順位 | 分類 | 左から右への並び順 |
| :---: | :--- | :--- |
| **第1優先** | **レアリティ** | コモン ➔ アンコモン ➔ レア ➔ エピック ➔ レジェンド |
| **第2優先** | **種族** | ドワーフ ➔ ドラゴン ➔ エルフ ➔ オーク ➔ ヴァンパイア ➔ リザードマン |
| **第3優先** | **属性** | 火 ➔ 氷 ➔ 風 ➔ 雷 ➔ 水 ➔ 地 |

## 4. カードの合成仕様および強調アニメーション

### 4.1. 合成条件と操作
* **合成条件**: **同レアリティ** かつ **同種族** のカード同士のみ合成可能。
* **合成操作**:
  * プレイヤーが所持しているカード同士（手札にある合成元カードに対して、手札内または出撃スロット内の別カード）をドラッグ＆ドロップする。
  * **ショップ・市場陳列カードの挙動**: ショップや解雇市場のカードを手札カードの上に重ねてドロップした場合は、合成は行われず**「手札への通常購入処理」**として実行される。
  * 条件を満たさない所持カード同士を重ねた場合（合成失敗）、特別なエラー通知は行わず操作は不成立となる。

### 4.2. 同レアリティ・同種族カードの強調アニメーション
カードにマウスホバー、またはドラッグを開始した際、合成可能な同レアリティ・同種族のカードに対して青色発光パルスアニメーション（`card-synth-highlight`）が再生される。

* **適用対象カードUI**:
  1. **手札UI** に表示されたカード
  2. **ショップ** に陳列されたカード（左右端の枠も含め完全表示）
  3. **解雇市場** に陳列されたカード
  4. **繰り出しUI（出撃スロット）** に配置されたカード
  5. **手札UIと繰り出しUIの間を移動（飛翔）中のカード**
* **対象外カードUI**:
  * 「〇〇の前ラウンド情報」モーダル内のカードUI
  * バトルリザルト画面のカードUI
  * Tipsモーダル内のカードUI
  * バトルフェーズ戦闘画面のカードUI
* **強調判定規約（完全整合ルール）**:
  1. **マウスオーバー・ドラッグ中カードが存在しない場合**: 同レア・同種族カードが複数存在していても、移動中のカードを含め、どのカードにも強調アニメーションは再生されない。
  2. **移動中のカードに対する判定**: 現在マウスオーバー・ドラッグされているカードと同レア・同種族であり、かつそのカード自身ではない場合にのみ強調アニメーションが適用される。
  3. **移動に伴う強調解除**: カードの移動完了やドロップ解除に伴い、発生していた周囲の強調アニメーションは即座かつ確実に終了・消滅する。

### 4.3. 合成結果
* 各スタッツ（HP, 攻撃, 素早さ）が合算される。
* **★バッジの数値が合算される**（例：★1 ＋ ★1 ＝ ★2、★1 ＋ ★2 ＝ ★3）。
* 素材カードは消滅する。
* 合成元または素材に「解バッジ」があっても、**合成後のカードには「解バッジ」を引き継がない**（通常のカードとなる）。

## 5. 出撃スロットと解雇（売却）操作

### 5.1. 繰り出しUI（出撃スロット）および枠線クリップ根絶・表示優先度規約
* 手札から最大3枚までを出撃スロット（番号1～3）にドラッグ＆ドロップで配置する。
* **完了ボタンの内蔵**:
  * 出撃スロット3枠の右隣に、横幅約136pxの大型 **「完了」ボタンが一体化して内蔵配置** される。
* **枠線クリップ根絶およびカード枠線の表示優先度規約**:
  * スロットにカードが配置された際は、スロット要素自体のボーダー幅を0（`border-width: 0 !important;`）にし、かつ `overflow: visible !important;` を適用する。
  * これにより、スロット枠による切り落としを完全に排除し、カードUI本来のレアリティに応じた色付き枠線が最前面に100%優先表示される。
* **手札カードの自動配置・解除**:
  * 手札カードを右クリック（タッチ端末ではロングタップ）した際、最も手前の空き枠へ自動配置される。
  * スロットのカードを右クリックすると即座に手札へ戻る。先行アニメーション中であってもディレイなく（0ms）連続で受け付けられる。

### 5.2. カードの解雇（売却）エリア
* **レイアウトおよび正方形デザイン**:
  * 出撃スロットの右隣に、独立したすりガラス枠として配置される。
  * 上部見出しテキスト「売却」は配置せず、解雇ボックス自体は **130px × 130px の完全な正方形（1:1）デザイン** を維持する。
* **獲得ゴールドの計算式**:
  * **解バッジなし**: $\lfloor \text{ショップ購入額} \times \text{★バッジの数値} / 2 \rfloor$
  * **解バッジあり**: $\lfloor \text{ショップ購入額} \times \text{★バッジの数値} / 4 \rfloor$

## 6. 準備完了フローと確認モーダル

プレイヤーが「完了」ボタンをクリックした際、以下の優先度でチェックが行われる。

1. **脱落プレイヤーの操作無効化**:
   * すでに脱落したプレイヤーは、「完了」ボタンおよびリロールボタンが恒久的に非活性（グレーアウト）となり、クリックしても一切の準備完了処理は受け付けられない。
2. **繰り出しカードが0枚の場合（優先チェック）**:
   * 出撃スロットのカードが0枚の場合、以下の確認ダイアログを表示する。
   > 繰り出すカードを選択していません。  
   > 本当に完了しますか？  
   > [はい] / [いいえ]
   * 「はい」を選択した際、手札が7枚以上の場合は直ちに超過売却モーダルへ移行する。
3. **手札7枚以上の場合（手札超過解雇モーダル）**:
   * 手札が6枚以下になるまで売却するカードを選択させるモーダルを表示する。
   * 出撃スロット配置カードは保護され、クリック時は「現在、出撃中のカードです」と通知される。
   * 手札が6枚になった時点で、改めて完了ボタンを押すことなく自動的に待機状態へ移行する。
4. **準備完了後**:
   * 「完了」ボタンは非活性となる。
   * 画面中央上部に **「全員の準備完了を待っています...」** のアナウンスメッセージが表示され、バトルフェーズが開始されるまで維持される。

## 7. 他プレイヤー枠と前ラウンド情報

### 7.1. 対戦相手サイドバー（動的伸縮・手札接触時縦スクロール・他UI干渉回避規約）
* **動的サイズ伸縮**:
  * 参加者の人数およびプレイヤー名の長さに応じて、**表示領域の縦横サイズが動的に伸縮（`width: fit-content; min-width: 180px; max-width: 320px; height: fit-content;`）**する。
  * プレイヤー名が長い場合でも省略記号「…」で切られることなく全文が表示される。
* **手札UI接触時の拡張停止および縦スクロール化（改修後正式仕様）**:
  * 対戦相手の人数が多く縦方向に伸びた結果、**下段の手札UI上端に接触しそうになった場合は、手札UIの手前でそれ以上の縦拡張を自動停止**する。
  * 拡張が停止した後は、サイドバー内部のプレイヤーリスト（`.opponents-vertical-list`）が自動的に**縦スクロール可能（`overflow-y: auto`）**となり、手札UIを押し潰したり干渉することなく全対戦相手を閲覧できる。
* **他UIへの影響抑制および接触時スマート退避制御（改修後正式仕様）**:
  * サイドバーが伸縮しても、画面中央に配置されているメイン作業UI（ショップ・出撃・手札）の配置が不必要にずれることはなく、**通常時は画面水平中央配置が厳格に維持**される。
  * サイドバーが横に伸びて**メイン作業UIに接触しそうになった場合に限り、干渉を避けるために必要な最小限の距離だけメイン作業UIを右へ自動退避**（`translateX`）させる。接触が解消された場合は瞬時に元の画面中央へ復帰する。

### 7.2. 「〇〇の前ラウンド情報」モーダル（中央揃え配置）
生存プレイヤーの枠をクリックすることで、前ラウンドの出撃情報モーダルを開くことができる。
* **カード配置の中央揃え**:
  「繰り出したカード順」および「控えカード」のカードUIグリッド（`.history-card-grid`）は、**横方向の中央揃え（`justify-content: center`）で美しく配置**される。
* 相手自身のカード構成に基づく種族補正スタッツの**数値部分のみを緑色**で表示し、弱点属性は丸型属性アイコンで表示される。

## 8. 待機状態ランプの状態遷移規約

待機状態ランプは、以下の通り全プレイヤーの画面にリアルタイム同期される。

1. **準備フェーズ開始時**: 全員 **消灯**
2. **準備完了時**: 「完了」ボタンを押した生存プレイヤーが **点灯**
3. **バトルフェーズ開始時**: 全員 **消灯**
4. **バトルリザルト確認後**: 「次へ」ボタンを押したプレイヤーが **点灯**
5. **次ラウンド準備フェーズ移行時**: 全員 **消灯**
