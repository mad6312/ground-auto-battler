# グラウンド・オートバトラー 正式仕様書 - 04: 最終リザルト・ロビー・システム仕様

---

## 1. 最終リザルト・ゲーム終了仕様

### 1.1. ゲーム終了および優勝判定
* **単独優勝**: 生存プレイヤーが **1名** になった時点でゲーム終了となり、そのプレイヤーが1位（単独優勝）となる。
* **同時優勝（全員同時全滅）**: 最終ラウンドに残っていたプレイヤー全員が同時に敗北し、生存者が0名になった場合は、その最終ラウンドで同時に脱落した全員を **1位（同時優勝）** とする。
* **例外処理（全員切断時の優勝者なし）**:
  生存者がいる状態で全生存者が切断等により0名になった場合、残された脱落プレイヤーを不当に繰り上げ優勝者とはせず、**例外的に「優勝者なし」として処理し、VICTORYボックスは絶対に非表示**とする。順位表においても脱落者が1stとして表示されることはない。
* **バトル終了とゲーム終了移行（要件）**:
  * 優勝者が決定する最終ラウンドであっても、**バトルの実行前に最終リザルト画面へ早期遷移することは絶対にない**。
  * 通常通りバトル演出および対戦結果モーダルを確認した後、**各プレイヤーが自発的に「次へ」を押した段階で最終リザルト画面へ遷移**する（閲覧中に他プレイヤーの操作によって強制遷移されることはない）。
* **切断による即時ゲーム終了**: プレイヤーの切断により生存者が1名以下になった場合は、即座に最終リザルト画面へ遷移する。
* **モーダル全閉によるソフトロック防止**: 最終リザルト画面表示時、手札超過モーダルや確認ダイアログなど開いている全てのモーダルは一括で閉じられ、手札超過準備フラグ等の入力待機フラグも完全初期化される。最終リザルト画面は最前面レイヤー（`z-index: 1500`）に配置される。

### 1.2. 最終順位の決定規則
順位は以下の優先順位に従って厳格に決定される。同順位のプレイヤーが存在する場合、次の順位番号はその人数分だけ繰り下げられる。

1. **生存プレイヤー**: 残りライフ数に関わらず上位（単独生存時は1位）。
2. **強制終了時の生存者**: 残りライフの降順で順位付け（同ライフの場合は同順位）。**残りライフ同値で1位が複数名いる場合は同時優勝扱い**となる。
3. **脱落プレイヤー**: 脱落したラウンド番号（`eliminatedRound`）の降順で整列（遅いラウンドで脱落したプレイヤーほど上位）。同じラウンドで脱落したプレイヤー同士は **同順位** とする。
4. **切断プレイヤー**: ゲーム途中に切断したプレイヤーは、最下位行に表示される。

### 1.3. 順位表記とカラー設定
* **1st**: 金色 (`#facc15`, 太字)
* **2nd**: 銀色 (`#e2e8f0`, 太字)
* **3rd**: 銅色 (`#cd7f32`, 太字)
* **4th以下**: 白色 (`#ffffff`, 太字)
* **切断**: グレー (`#94a3b8`, イタリック)

### 1.4. 残りライフの表示色
順位表に表示される残りライフ（例: `♥♥♥♥♥`）は、白色ではなく**ゲーム中と同じ赤色 (`#ef4444`)** で表示される。

### 1.5. 切断プレイヤーの表示維持
ゲーム途中に切断したプレイヤーについても最終リザルト画面から除外せず、以下の形式で行を保持して表示する。

| 順位 | プレイヤー名 | 残りライフ |
| :---: | :--- | :---: |
| **切断** | 切断したプレイヤー名 | **-** |

### 1.6. 優勝者専用ハイライト演出（VICTORYボックス）
優勝者が決定した際、王冠アイコン（👑）と黄金の光彩アニメーションによる **VICTORY ボックス** が画面上部に表示される。
* **単独優勝時**: 優勝者の名前が単独で表示される。
* **同時優勝時（通常・強制終了含む）**: 同時優勝となったプレイヤー全員の名前が連名（`〇〇 & △△`）で強調表示される。
* **優勝者なし時**: VICTORYボックスは非表示となる。

### 1.7. 再戦・退出操作および2試合目以降の進行保証（要件）
* **「再戦」ボタン**:
  * 押した本人のみが即座にロビー画面へ遷移し、新品の初期ライフ（5）・初期ゴールド（20G）・空の手札・出撃枠の状態で再戦エントリー状態（参加中）となる。
  * サーバー側ではゲーム進行状態が安全に `'lobby'` にリセットされ、前試合の結果画面に残っているプレイヤーがいても、ロビーへ復帰したプレイヤー間でのゲーム進行は一切阻害されない。
* **「退出」ボタン**:
  * 押した本人のみがルーム参加リストから除外され、未エントリー状態で確実にロビー画面へ復帰する。
* **2試合目以降のゲーム開始保証**:
  * 1試合目終了後にゲームロビー画面へ戻った場合でも、ホストの画面には参加人数が2人以上になった時点で確実に「ゲーム開始」ボタンが表示される。
  * ホストが「ゲーム開始」ボタンを押下した際、前試合の残留データに影響されることなく、全参加プレイヤーの初期ショップ・初期配布カードが新規生成され、第2試合以降が正常に開始される。

## 2. ロビー・エントリー機能

### 2.1. エントリーボタン
* 「参加する」と「参加キャンセル」を切り替えるトグルボタン。
* ロビー画面表示中は常時クリック可能であり、接続・切断が発生しても動作が保証される。
* **10人上限の厳格適用**: 現在のエントリー人数が10人に達している場合、未エントリーのプレイヤーが「参加する」を押してもエントリーは受け付けられない。

### 2.2. 切断・再接続時のクライアント完全初期化
クライアントが切断・再接続した場合、クライアント内の手札・ショップ・スロット・モーダル等の内部状態は自動的に完全リセットされ、未参加状態でロビー画面へ復帰する。

### 2.3. 参加状況とバッジ表示
* 現在のエントリー人数（`○ / 10`）をリアルタイム表示。
* 状態バッジ: `未エントリー` / `参加中... 他のプレイヤーを待っています` を同期。

### 2.4. ホスト権限とゲーム開始
* 最初に接続したプレイヤーが自動的にホストとなる。ホスト切断・退出時は残存プレイヤーへ自動委譲される。
* エントリー人数が2人以上になると、ホストにのみ「ゲーム開始」ボタンが表示され、クリックでゲームを開始できる。

## 3. 「Tips」機能（ガイドモーダル）

### 3.1. 「Tips」ボタン
* 画面右上の「⚙ 設定」ボタンの左隣に **「💡 Tips」** ボタンを配置。
* ロビー画面およびゲームプレイ中の両方から利用可能。

### 3.2. ウィンドウサイズ固定とレイアウト
タブを切り替えてもウィンドウサイズが伸縮しないよう、モーダル全体の幅（720px）と高さ（560px）が固定されている。コンテンツはウィンドウ内で縦方向中央に配置される。

### 3.3. タブ構成と表示内容

#### ① 「属性」タブ
上部に以下の2つの**三角形（△）型属性相性図**を横並びで表示する。
* **属性相性図 1**: 火 ➔ 氷 ➔ 風 ➔ 火（火は氷に強く、氷は風に強く、風は火に強い）
* **属性相性図 2**: 雷 ➔ 水 ➔ 地 ➔ 雷（雷は水に強く、水は地に強く、地は雷に強い）

下部説明文:
> 属性は、攻撃時の弱点・耐性判定に関与します。  
> **弱点属性への攻撃：** 攻撃側が与えるダメージが2倍になります。  
> **耐性属性への攻撃：** 攻撃側が与えるダメージが1/2になります。

#### ② 「種族」タブ
上部説明文:
> 手札に同種族カードが2枚以上ある場合、その種族のカードが1枚増えるごとに、対象スタッツの補正倍率が10%または5%ずつ上昇します。

下部に種族別の補正スタッツ・倍率表（ドワーフ: HP 10%、ドラゴン: 攻撃 10%、エルフ: 素早さ 10%、オーク: HP・攻撃 5%、ヴァンパイア: HP・素早さ 5%、リザードマン: 攻撃・素早さ 5%）を表示する。

#### ③ 「合成」タブ
上部説明文:
> レアリティと種族が同じカード同士は合成することができます。

中央に合成例を実際のカードUI（2行レイアウト、購入額表記なし）を用いて横並びで表示する。
* **合成元**: 焔刃のエルフ (Flameblade Elf) [火/エルフ/★1] ❤2 / ⚔1 / ⚡7
* **記号**: ＋
* **素材**: 霜精のエルフ (Frost-Spirited Elf) [氷/エルフ/★1] ❤1 / ⚔3 / ⚡6
* **記号**: ＝
* **合成後**: 焔刃のエルフ (Flameblade Elf) [火/エルフ/★2] ❤3 / ⚔4 / ⚡13（ゴールド発光枠）

下部説明文:
> 合成の素材にするカードを、合成元にするカードへドラッグ＆ドロップすることで、合成後のカードの各スタッツがそれぞれの合計値になります。  
> また、カード名・レアリティ・属性・種族は、合成元カードの情報が引き継がれます。

## 4. 設定モーダル（画面右上 ⚙設定）

* **プレイヤー名変更**:
  * ラベル表示: **「名前:」**
  * ボタン表示: **「変更」**（ボタン内の文字が改行されず1行で表示）
  * マッチング維持の原則: プレイヤーが名前を変更しても、すでに決定している対戦相手のペアリングが再抽選されることは絶対にない。準備フェーズ中のみ相手へ新しい名前が通知される。
* **ゲームの強制終了**:
  * ゲーム進行中、ホストにのみ「ゲームを強制終了」ボタンが表示される。
  * クリック時、**ホスト設定モーダルは即座に閉じられ、確認ダイアログが単独で表示される**。
  * 承認されるとその時点の生存プレイヤーを残りライフ降順（同値は同順位）で順位付けし、その後に脱落者を脱落ラウンド順で配置してゲーム終了画面へ移行する。残りライフ同値で1位が複数名の場合は同時優勝として連名表示される。

## 5. 入力操作・ドラッグシステムの設計規約

* **Pointer Eventsカスタムドラッグ**:
  ブラウザネイティブのDrag & Dropを使用せず、Pointer Events（`pointerdown`, `pointermove`, `pointerup`, `pointercancel`）によるカスタムドラッグを採用する。
* **ウィンドウ監視によるドラッグ追従と安全解放**:
  * イベントは `window` 単位で一括監視され、ドラッグ中にDOM再描画が発生してもゴースト要素が取り残されることはない。
  * マウスボタンが離された状態（`e.buttons === 0`）を検知した場合、およびブラウザウィンドウからフォーカスが離脱（`blur`）した場合は、直ちにドラッグを安全にキャンセルし、意図しない自動売却やカード消失を防止する。
