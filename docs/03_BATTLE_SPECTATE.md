# グラウンド・オートバトラー 正式仕様書 - 03: バトルフェーズ・観戦仕様

---

## 1. マッチング仕様

### 1.1. マッチングタイミングと対戦相手表示
対戦相手のマッチング処理は、**各ラウンドの開始時（準備フェーズ開始時）** に行われる。
* 画面左上の「ラウンド:〇」の右隣に、**「次の対戦相手:〇〇」** が準備フェーズ中から正確に表示される。
* **表示対象の制御**: 脱落していない生存プレイヤーにのみ表示される。バトルリザルト画面で「次へ」をクリックして待機状態になった際は非表示となり、次ラウンド開始時に再び新マッチングが表示される。

### 1.2. 過去の対戦履歴に基づく再マッチング回避（全組み合わせ探索による再戦コスト最小化）
マッチングを作成する際、そのゲーム中に**すでに対戦したことがある相手との再マッチングを可能な限り回避**する。
* **対戦回数の厳格管理**: 各プレイヤー間の過去対戦回数は個別に累積カウント（Count Map）され、対戦経験のないペアが最優先される。
* **通常対人戦と影戦のコスト分離**: 生身のプレイヤー同士の対戦（PvP）の再戦コストを、影戦（PvE）の再戦コストより大幅に高く重み付け（対人: 回数×100、影: 回数×10）し、対人未対戦カードを最優先でマッチングする。
* **直前PvP連続対戦の絶対回避**: 直前ラウンドで**生身同士で対戦したペア**にのみ巨大な直前対戦ペナルティ（+1000）を課す。影戦の相手が生身の直前対戦相手と誤認されることはなく、人数が3人以上いる限り、2ラウンド連続で同一の生身対戦カードが組まれることは原理的に完全排除される。
* **全組み合わせ最適化**: Fisher-Yates シャッフルによる公平な初期化を行った後、総当たり全探索アルゴリズムによって全組み合わせの中からコスト総和が真に最小となる最適マッチングを選定する。

### 1.3. 「(影)」の選定と完全均等ローテーション規約
生存プレイヤー数が奇数の場合、余ったプレイヤーに対戦相手のコピー「(影)」を割り当てる。
* **影戦担当プレイヤーの完全均等ローテーション**:
  1. 奇数人数時、影と戦うプレイヤー（`oddPlayer`）を選定する際、**過去の影戦累計回数が最も少ないプレイヤー（最小回数）を最優先で選出**する。回数が多いプレイヤーが選ばれることには特大ペナルティが課される。
  2. 直前ラウンドで影と戦ったプレイヤーには直前影戦連続ペナルティが課され、連続して影戦が割り当てられることはない。
  3. これにより、3人戦（3 ➔ 1 ➔ 2 ➔ 3...）をはじめ、5人・7人・9人戦においても、特定プレイヤーに影戦が偏ることなく、全員が完全に1回ずつ均等に影戦を担当する完全巡回サイクルが保証され、対戦組み合わせの固定化ループは完全に根絶される。
* **影の提供元の最適選定**:
  * 影の提供元（`ghostSource`）を選定する際も、過去対戦回数の少ないプレイヤーの影が優先して割り当てられる。
* **対戦履歴の記録規約**:
  * 影戦を行った際、両者の累積対戦履歴に対称に対戦回数が記録される（仕様厳守）。
  * ただし、影戦相手が生身の直前対戦履歴（`lastPvPOpponents`）に混入することはなく、生身対人戦の直前連続判定とは明確に分離して管理される。
* コピーが敗北しても、コピー元の本体プレイヤーのライフは減少しない。

### 1.4. 準備フェーズ中の切断と再マッチング
準備フェーズ中に対戦相手が切断した場合、自動的に他プレイヤーの「(影)」と即座に再マッチングが行われ、「次の対戦相手:〇〇」の表示もリアルタイムで更新される。

## 2. バトルフェーズ開始時の画面・カード制御

### 2.1. 手札超過カードの自動解雇
準備フェーズで7枚以上の手札が残ったままバトルフェーズへ移行した場合、**バトル開始時**に手札が6枚になるまで控えカードからランダムに自動解雇（売却）される。
* 出撃スロット配置カードは対象外。
* ショップ購入額・★バッジ数値・解バッジに応じた売却ゴールドが即座に所持金へ加算される。

### 2.2. ショップおよび解雇市場の非表示化
各ラウンドのバトルフェーズ開始時、ショップおよび解雇市場に陳列されているカード（「売却済み」表示を含む）はすべて画面上から非表示となる。
* 解雇市場タブの表示は一時的に **`解雇市場(0)`** となる。
* 準備フェーズ以外でのリロール操作はボタンがグレーアウトされ無効化される。
* 次ラウンドの準備フェーズ開始時に再びカードが正常に陳列される。

## 3. バトル画面レイアウトと演出

### 3.1. 画面レイアウトの完全固定化
* **自分自身の左側固定**: 先攻・後攻・マッチングによらず、**自分自身のカードが必ず画面左側**、対戦相手のカードが必ず画面右側に配置される。
* **プレイヤー情報・インジケーターの分離固定**: プレイヤー名および残り出撃枚数インジケーターは、カードのアニメーションスロットと完全に分離され、カードが攻撃・被弾で動いても所定位置に固定される。

### 3.2. 残り出撃カード枚数の表示（●〇インジケーター）
プレイヤー名の下に、出撃カードの残数をリアルタイムに「●」「〇」で表示する。
* **表示規則**:
  * 3枚出撃時: `●●●` ➔ 1枚倒されると `●●〇` ➔ `●〇〇` ➔ `〇〇〇`
  * 2枚出撃時: `●●` ➔ `●〇` ➔ `〇〇`
  * 1枚出撃時: `●` ➔ `〇`
* **減少タイミングの厳格化**:
  * カードが戦闘不能になった瞬間のログ（`〇〇は倒れた！`）において、**即座に対象側の残存数が1減少し、●が〇へと変化**する。次カードの繰り出しログまで減少が遅れることはない。

### 3.3. 出撃カード0枚時のバトル画面表示
* **片方の出撃カードが0枚の場合**:
  * 片方のプレイヤーが出撃カード0枚であっても、もう片方のプレイヤーに出撃カードが1枚以上ある場合は、**そのプレイヤーの出撃カードの1枚目をバトル画面のスロットに正常に表示**する。
  * 出撃カードが存在する側の表示まで非表示化されることはない。
* **勝敗判定の維持**:
  * 出撃カードが0枚の側が強制敗北となる。両プレイヤーとも0枚の場合は両者敗北（両者ライフ -1）。

### 3.4. 戦闘演出と残HPリアルタイム反映
1. **攻撃動作**: 相手方向へ踏み込むアニメーション。
2. **被弾動作**: 揺れ動きと赤色フラッシュ。
3. **回避動作**: 身を引く回避アニメーションと「MISS」のポップアップ。
4. **ダメージポップアップ**: 通常白、弱点橙赤、耐性水色、会心金色。
5. **残HPのリアルタイム更新**: ダメージを受けるたびにカードUI上のHP数値が最新残HPへ更新される。種族補正カードは**数値部分のみ緑色 (`#22c55e`)** を厳格に維持する。
6. **HP0消滅と復活見え防止**: HPが0になったカードは消滅アニメーションとともに完全除去される。
7. **ログの最新行自動スクロール**: 新しいログが追加されるたび最新行へ自動スクロールされる。
8. **バックグラウンドタブ時の自動スキップ（30秒猶予）**: ブラウザタブが非アクティブ状態になった場合、30秒間の猶予タイマーが作動し、30秒以内に復帰しなかった場合はタイマー間引きによる全体遅延を防ぐため演出が自動スキップされる。復帰した場合は通常演出を継続する。

## 4. 戦闘シミュレーション計算

戦闘は完全自動で進行する。

* **攻撃順**: 素早さが高いカードから先攻。同値はランダム（50%）。
* **命中率とダメージ計算式**:
  1. 基本ダメージ ＝ 攻撃側カードの攻撃スタッツ
  2. 命中判定 ＝ 命中率 $\approx 91.67\%$（外れた場合は 0 ダメージ）
  3. クリティカル判定 ＝ 命中時 1/6 で発生（ダメージ 1.5倍）
  4. 属性相性倍率 ＝ 弱点 2.0倍、耐性 0.5倍、等倍 1.0倍
  5. 端数処理 ＝ 各種補正後の最終ダメージは **四捨五入**。
  6. 最低ダメージ保証 ＝ 通常ヒット時は最低 1、クリティカル発生時は **最低 2**。
* **ターン上限と判定（300ターン）**:
  * 300ターン到達時は、以下の順序で勝敗を判定する。
    1. **残存カード枚数** の多い側を勝者とする。
    2. 残存枚数が同数の場合、**残りHP比率**（$\text{残りHP合計} \div \text{出撃時総HP}$）の多い側を勝者とする。
    3. 比率も同値の場合は引き分けとする。
* **勝敗と引き分け**: 出撃カードが全滅した側が敗北（ライフ -1）。**引き分け時は両者ともにライフが 1 減少する**。

## 5. バトルリザルト仕様

対戦終了後、バトルリザルトモーダルが表示される。

### 5.1. 戦闘ダメージ詳細の3列構成と遺影表現
左側に「戦闘ダメージ詳細」、右側に「バトル経過ログ」を独立して配置する。
* **全スクロールバーの初期位置リセット**:
  モーダルが表示され、テーブルおよびログの内容がDOMに構築された後、**テーブルやログ等のすべてのスクロールバーが最上部（0）にリセット**される。
* **3列ヘッダー構成**: テーブル構成は **「自分」「相手」「与えた合計ダメージ」** とする。
* **全交戦カード組み合わせの1行表示**:
  そのバトル中に戦闘を行ったすべてのカード組み合わせについて、左列（自分）、中央列（相手）、右列（与えた合計ダメージ・中央揃え）で表示する。片方0枚出撃時も、出撃側のカードが正常に1行表示される。
* **先にHP0になったカードの遺影表現**:
  各戦闘で**先にHPが0になったカードのUIに遺影のような視覚表現（モノクロ・コントラスト強調・専用黒枠ボーダー）を適用**する（属性バッジの視認性は維持される）。
* **バトル経過ログの常時展開**: 経過ログは最初から常に展開されて表示される。

### 5.2. ライフ変化の表示制御（事前ネタバレ防止）
* **「次へ」押下までライフ変化を隠蔽**:
  バトルフェーズ中に発生した各プレイヤー（自分および他プレイヤー全員）のライフ変化、およびそれに伴う脱落状態（観戦ボタンの先行出現など）は、**自分がバトルリザルト画面で「次へ」ボタンを押下するまで、自分の画面には反映しない**。
* 「次へ」ボタンを押下した瞬間に初めて最新のライフ値および脱落状態が画面へ反映・更新される。

### 5.3. 「次へ」ボタン押下フローと待機・観戦復元
* モーダルが閉じ、最新のライフ変化が画面へ反映される。
* **優勝決定時の遷移保証（要件）**:
  * 優勝者が決定する最終ラウンドであっても、**バトルの実行前に最終リザルト画面へ遷移することは絶対にない**。
  * 通常通りバトルフェーズが実行され、バトルリザルト画面を確認した後、**各プレイヤーが自発的に「次へ」を押した段階で最終リザルト画面へ遷移**する。
* **通常ラウンドの遷移**:
  * 決着未確定時は、自身の待機ランプが即座に点灯し、画面上部に「全員のバトル終了を待っています...」のアナウンスが表示される。
  * 生存プレイヤー枠に「観戦」ボタンが表示され、他者のバトルを観戦可能となる。
* **観戦終了後のバナー復元保証**:
  * 待機中のプレイヤーが他者のバトルを観戦し、観戦リザルトの「次へ」を押して観戦を終了した際、自身の待機状態および「全員のバトル終了を待っています...」のアナウンスバナーは確実に再表示・復元される。

## 6. 観戦機能および観戦予約仕様

### 6.1. 非脱落プレイヤーの観戦
バトルリザルト画面で「次へ」をクリックした非脱落プレイヤーは、プレイヤー枠の **「観戦」ボタン** をクリックしてリアルタイム観戦画面へ移行できる。
* **ラウンド跨ぎ時および観戦終了時の挙動**:
  * 観戦中に次ラウンドへ進んだ場合でも観戦を継続し、観戦リザルトの「次へ」を押した際は単にモーダルを閉じるのみで、自身の次ラウンド準備フェーズ（待機ランプ消灯状態）に悪影響を与えない。
  * バトルフェーズが継続中の場合は、待機アナウンスバナーが正常に復元される。

### 6.2. 脱落プレイヤーの観戦予約機能
脱落プレイヤーの画面では、準備フェーズ中に対戦相手枠に **「観戦予約」ボタン** が表示される。
* **予約トグル**: 「観戦予約」クリックで予約有効（「予約解除」へ変化）。
* **自動遷移**: バトルフェーズ開始通知により、予約していたプレイヤーのバトル観戦画面へ自動遷移する。
* **予約の継続**: 自動遷移で観戦した場合、次ラウンド開始時もそのプレイヤーの「観戦予約」が有効な状態が引き継がれる。予約相手が脱落した場合は自動的に解除される。
